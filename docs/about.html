About Expressive Assets, and the tools around it

An asset library that tools can read

Expressive Assets is the icon and illustration library for Windows Design Systems, together with the tools built on top of it. Artwork is designed in Figma, imported through a reviewed plan, and stored as flat SVG with metadata beside it. A build step turns that tree into one file, manifest.json, and everything downstream reads only that.

That single rule is what makes the rest possible. A tool never walks the asset folders, so adding a collection, a style or a size changes nothing in the tools. It is also why a new tool takes an afternoon rather than a sprint.

The tools

Gallery Live Browse and search the whole library. Filter by collection, style and size, preview against light and dark, copy or download any drawing. Customizer Live Apply an icon style across a set of twelve at once and tune it: palette, stroke, texture, surface. Any slot swaps for anything in the library.
Builder Later Compose illustrations from reusable pieces. Waits on the illustration cleanup and an agreed illustration style.

Reference

System Map How the pieces fit together, end to end: Figma to plan to importer to the asset tree to the manifest, and the tools that read it. Includes the current state of the library and the decisions still open. Icon Anatomy Pilot Twelve product icons, and a proposed vocabulary for naming the parts inside an asset so they can be addressed individually. The work in progress right now.

How to read these

Both documents are working drafts rather than published specifications. They are written to be argued with: where something is undecided it says so, and the open questions at the end of each are genuinely open. If one of them is wrong, that is worth more to me than if it is agreed with.
