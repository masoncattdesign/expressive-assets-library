How an illustration gets made

Four modes, one language, and a linter that reads the output back. This is the whole pipeline: what each stage decides, what it hands on, and where the library plugs into it.

7 stages 4 modes 3 glyph sources 14 checks Builder 0.2

In one paragraph

You choose a mode, which sets the style preset and decides which slots you can bind. You choose the relationship between the feature's objects, which narrows the twelve layouts to the ones that carry it. You pick the layout. From there it is mechanical: the layout calls the shared primitives, the preset supplies the numbers and the token fallbacks, the glyph sources fill the slots, and the result is an SVG string on a 160 grid whose every color is a var(). That string is then parsed back and checked against the rules, which is the only honest way to know it obeys them. Nothing is written anywhere: the output is a download.

The pipeline, stage by stage

These are numbered because they really are a sequence. Each stage only decides what the one before it left open, which is why there is never a dialog asking you to resolve two things at once.

  • 1 · ModeSets the style preset and decides which slots can be bound. Windows, Pieces and Product UI run the compose path; Devices wraps that path in a frame. A mode is not a separate engine, and switching one mid-build keeps the feature, the layout and the glyph.
  • 2 · RelationshipContainment, convergence, sequence, mapping, hierarchy, selection, transformation, multiplicity, gating, accumulation. This is the decision that matters and the only one the tool cannot make for you. Changing it moves the layout to one that carries it, because leaving a mismatched layout selected is how a set stops meaning anything.
  • 3 · LayoutOne of twelve, each adapted from a finished illustration rather than composed fresh. The layout owns its panel geometry, its backdrop, its float and its card positions. The only thing a caller may vary is the row count, and only downward: the fade line at y 112 is the ceiling.
  • 4 · The languageThe primitives every layout calls, plus the preset that supplies the numbers. One stroke width, one stroke color, one gradient, at most one shadow, thirteen token slots. Three guards throw here rather than producing a subtly wrong drawing: a glyph that would overlap what it sits between, a rail that would start above its first node, and a card whose content would touch its own bottom edge.
  • 5 · SVGA string on a 160 grid where every color is var(--il-token, #fallback) and every id carries the feature's slug. In Devices mode this is where the frame is applied and the composition is nested into the screen rect, with its shadows switched off, because a screen is emissive.
  • 6 · ChecksThe string is parsed back and read against the rules. Running on the output rather than the intent is the whole point: a rule that checks what the code meant to do cannot catch the case where it did something else. They run on every keystroke.
  • 7 · ExportThe themed SVG, or a flat copy with the tokens resolved for one ground, or the brief. Flat exists because an <img> and Figma both refuse to run CSS, so a themed file shows only its fallbacks in either.

What the checks catch

Fourteen rules. Every one is a failure that shipped before it was a rule, which is the only reason to have it. A rule that cannot fail is decoration, so after fixing something the bug goes back in once to confirm the check catches it.

CheckWhat it catches
One stroke widthA second width creeping in, usually from a stroke with no stroke-width at all, which silently defaults to 1.
One stroke colorA second line color, which makes a panel edge and a card edge differ by the line rather than by the fills either side of it.
Shadow countMore than one element casting. Two is right only for the corner chip pair, and it says so rather than passing silently.
Shadow valuesA blur or offset outside the two the system has.
No textA <text> element. The language is placeholder bars, never words.
No imageA raster snuck into geometry.
No background rectA full canvas fill, which stops the fade dissolving into the host page and only looks right on one background.
CanvasA viewBox that is not the 160 square, or a baked in width or height on the root.
AccessibilityA missing role="img" or a missing label.
Id suffixesAn id without the feature's slug. Gradient and mask ids are document-global, so this is what stops two drawings on one page painting with each other's gradients.
Gradient countA second structural gradient. A device plus its nested screen legitimately has two, and the check knows the difference.
Fade stopsA fade that runs between different offsets from its siblings, which makes one illustration in a set dissolve at a different height.
Accent budgetMore than two accented elements, which means the accent is carrying meaning the composition should have carried.
LegibilityA glyph under 9 units, which is under 9 pixels at display size and simply disappears.

Where it meets the library

At exactly one place: manifest.json. Builder reads the manifest for the System Icon collection, then fetches one drawing at a time as tiles scroll into view, which is the same approach the Gallery settled on. It never walks the asset tree, so adding a collection, a style or a size changes nothing here.

Forty glyphs are baked into the page so it draws before any fetch: the ones the twelve layouts need plus a starter set. Everything else in the collection comes down on demand. Anything carrying its own colors is refused rather than recolored, because a tinted brand mark repainted with --il-stroke is a lie about the artwork, and that is why the product, app and file collections are not offered as glyph sources.

Nothing goes the other way. There is no path from Builder into assets/, on purpose: an asset entering the library needs a slug, a meta.json, provenance marked as generated rather than received, and the manifest and validate steps passing. None of that should happen through a browser.

Still open

The decisions this map is waiting on, as opposed to the features it is missing. The missing features are on About.

  • Two color modelsStage four has thirteen token slots from the exploration. Expressive Assets separately derives group and member color IDs per asset. Those are two answers to one question and only one of them is ours. Which one survives is entangled with the Bridge naming question, and nothing forces it while Builder emits no Bridge tokens.
  • Whether Windows is a presetMode one treats a Windows illustration as the twelve layouts at different settings. That is a real thing, and it is not the same as the WDS illustration set, which is scenes and objects rather than UI abstractions. If those need their own parts vocabulary then mode one grows a second engine after all, and the map changes.
  • What a slot may holdToday a slot takes a whole asset used as a glyph. The structural IDs exist so that an asset can supply a part, which would let a card hold a real plate and a real glyph. That is a different contract and it waits on the anatomy vocabulary.
  • PortraitThe tablet and the phone crop a square composition rather than showing one built for them. Portrait layouts would be new entries in the twelve, so this is a decision about the taxonomy rather than an addition to it.
