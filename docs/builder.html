An illustration is a composition, not a drawing

Builder makes product illustrations by choosing a relationship, picking the layout that carries it, and filling that layout with a fixed set of pieces. Nothing here is drawn freehand. The geometry, the single stroke and the thirteen color slots are the same in every output, which is what makes a set of twelve look like one family instead of twelve decisions.

What this is, and what it is not

This is the shell. One path works end to end: name a feature, say what the relationship between its objects is, pick the layout, and Builder composes a real SVG, checks it against the rules, and hands it back themed or flattened. That path is deliberately narrow, because the parts of the Builder that are hard are the parts underneath it, and a shell is how you find out whether they are the right parts.

The visual language is ported from a product illustration generator exploration rather than invented here. That exploration had already answered the questions that matter: how many layouts, what a stroke is allowed to be, which slots a palette has, and how to tell a composition from a screenshot. Builder is the interactive front end for it, so the answers stay in one place.

The standing rule, inherited and not negotiable: adapt, do not invent. Pick the nearest of the twelve, keep its geometry, change only the content. Every tool that follows this produces the same family. Every tool that composes from scratch drifts. Builder enforces it by having no way to move a coordinate.

    Where the library comes in
    
    
    The Phosphor set is the exploration's own icon source, and it is here because the layouts
    were drawn around it. The Library source reads manifest.json, the same contract
    every other tool on this site reads, and places a System Icon in the same slot. That is the
    seam where Builder stops being a port and starts being part of this library: a Windows
    illustration should be built from Windows marks, not from a general purpose icon set.
    
    
    
      Library not loaded yet
      
    
    
    
    System Icons are single path artwork on a 24 unit
    grid with a currentColor fill, which is exactly what this slot needs. Anything
    carrying its own colors is refused rather than recolored, and the refusal says so. Product and
    file icons are not offered yet for that reason.
    
  
    

  
    
    
    Not built yet
    
    
      
      
    • Composing from library partsToday the layout supplies the
      composition and the library supplies one glyph. The point of the structural IDs is that a
      library asset can supply a part, so a card can hold a real plate and a real glyph
      rather than a placeholder bar. That waits on the anatomy vocabulary settling, which is the
      open thread in Asset Anatomy.
      • 

      
    • Color roles instead of token slotsThe thirteen
      --il-* slots are the exploration's palette model. This library already derives
      group and member color IDs per asset. Those are two answers to one question, and the second
      one is ours. Reconciling them is a real decision, not a mapping, and it is worth making once
      the Bridge naming question in NEXT.md lands.
      • 

      
    • Sets, not single illustrationsLayout reuse across a set is the
      thing that makes a family read as designed. The contact sheet above shows the twelve, but
      Builder cannot yet hold a named set, budget layout reuse across it, or tell you that the
      fourth illustration is the third header card.
      • 

      
    • Writing backNo output lands anywhere. An illustration built here
      is a download. Getting it into assets/ means a slug, a
      meta.json, provenance marked as generated rather than received, and
      npm run manifest && npm run validate passing. None of that is wired,
      on purpose: nothing should enter the library through a browser.
      • 

      
    • FigmaThe sync plugin writes components one way. A flat export
      pastes into Figma correctly today, which is why the flat buttons exist, but that is a
      clipboard, not a pipeline.
